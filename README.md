# VLESS + Telegram WEB Proxy

Одна команда устанавливает VLESS-клиент, Telegram WEB Proxy, HTTPS и собственную веб-панель управления подключениями. Пользователь вводит **VLESS-ссылку, домен и email**. Пароль панели и секреты подключений создаются автоматически.

Установщик и панель написаны в этом проекте. Скрипты из видео и чужие установщики не используются. В `install.sh` уже встроены все собственные исходники; зависимости скачиваются из официальных репозиториев по зафиксированным версиям и SHA-256.

## Быстрый запуск

На **отдельном сервере с Ubuntu 22.04+ или Debian 12+**, подключившись по SSH:

```bash
curl -fsSL https://raw.githubusercontent.com/ievq00/vless-telegram-installer/main/install.sh | sudo bash
```

Если `curl` ещё не установлен:

```bash
sudo apt-get update && sudo apt-get install -y curl
```

Затем введите:

1. Полную ссылку `vless://…` — при вводе она скрыта.
2. Домен, например `proxy.example.com`, без `https://` и пути.
3. Email для HTTPS-сертификата.

Перед запуском создайте DNS-запись **A → публичный IPv4 этого сервера**. Отключите CDN-проксирование домена. Запись AAAA нужна только для действующего IPv6 этого же сервера. В панели хостинга должны быть разрешены входящие **TCP 80 и 443**; сохраните доступ по SSH.

Понадобятся root/sudo, systemd, архитектура amd64 или arm64, не менее 1.6 ГБ свободного диска; рекомендуется 2 ГБ оперативной памяти. Нужен доступ к репозиториям ОС и GitHub для начальной загрузки. Сборка занимает несколько минут в зависимости от сервера и сети.

Установщик проверяет VLESS и получает настоящий ответ `resPQ` от Telegram через всю цепочку. После успешной проверки он показывает ссылку подключения, адрес панели, логин `admin` и случайный пароль. Эти данные доступны повторно:

```bash
sudo cat /etc/vless-telegram/access.txt
```

## Совместимость Telegram

Это **WEB Proxy** с HTTPS-транспортом. Нужна версия Telegram, поддерживающая именно этот тип прокси. Обычный клиент без WEB Proxy использовать такую ссылку не сможет.

В [проекте Telegram](https://github.com/telegramdesktop/tproxy-server#6-configure-a-telegram-client) описаны реализация для Desktop, экспериментальный Android-клиент и план для iOS. Поддержка не гарантируется во всех магазинных версиях. Если `t.me/webproxy` открывает обычную веб-страницу, передайте домен и секрет непосредственно в поддерживающий WEB Proxy клиент; он также может принимать `tg://webproxy`.

## Что устанавливается

```text
Telegram с поддержкой WEB Proxy
  → HTTPS :443 / Caddy
  → Telegram WEB relay
  → MTProto backend
  → локальный SOCKS / sing-box
  → ваш VLESS-сервер
  → Telegram
```

Через VLESS направляется трафик Telegram-прокси. Установщик сохраняет обычную маршрутизацию сервера и SSH; глобальный TUN не создаётся.

Панель на случайном HTTPS-адресе позволяет создавать до 32 отдельных подключений, копировать ссылки, показывать QR-коды, отключать, удалять и заменять секреты. Изменения автоматически применяются и кратковременно переподключают активных пользователей. Последнее включённое подключение отключить нельзя. Адреса панели и пароли сохраняются при повторной установке.

Основные службы:

| Служба | Назначение |
| --- | --- |
| `vt-vless` | sing-box, VLESS-клиент и SOCKS на 127.0.0.1:1080 |
| `vt-backend` | MTProto backend на 127.0.0.1:2398 |
| `vt-relay` | WEB relay на 127.0.0.1:8080, внутренний admin 8081 |
| `vt-panel` | Панель на 127.0.0.1:8090 |
| `vt-caddy` | Публичные HTTP/HTTPS, получение и продление сертификатов |
| `vt-sync.path` | Применение изменений подключений |

Промежуточные порты доступны только внутри сервера. Если UFW уже включён, установщик добавляет разрешения для 80/443. Политика firewall, SSH и правила хостинга управляются отдельно. Занятые порты на первой установке приводят к остановке с объяснением.

## VLESS-ссылки

Поддерживаются TCP/raw с TLS или REALITY, Vision, WebSocket, gRPC и HTTP/H2 в формате VLESS URI. Сертификаты TLS проверяются по умолчанию; явно переданное `allowInsecure=1` отключает эту проверку. XHTTP, KCP, QUIC и неизвестные параметры отклоняются с пояснением.

Полный запуск проверен на Ubuntu 24.04 amd64 с TCP VLESS. Остальные поддержанные форматы проверены на разбор параметров, но не на реальное соединение с каждым типом сервера. Формат исходящего соединения соответствует [документации sing-box](https://sing-box.sagernet.org/configuration/outbound/vless/).

## Повторный запуск и смена настроек

Повторите команду быстрого запуска: сохранятся домен, VLESS, пользователи, секреты, пароль и путь панели. Для изменения трёх входных параметров:

```bash
curl -fsSL https://raw.githubusercontent.com/ievq00/vless-telegram-installer/main/install.sh | sudo bash -s -- --reconfigure
```

Для установки без вопросов создайте JSON-файл с правами `600`:

```json
{
  "vless_uri": "vless://YOUR_UUID@vless.example.com:443?security=tls&type=tcp&sni=vless.example.com",
  "domain": "proxy.example.com",
  "email": "admin@example.com"
}
```

```bash
sudo chmod 600 /root/vless-telegram.json
curl -fsSL https://raw.githubusercontent.com/ievq00/vless-telegram-installer/main/install.sh | sudo bash -s -- --config /root/vless-telegram.json
```

Добавьте `--check-config`, чтобы проверить формат без установки. Храните файл с VLESS и `/etc/vless-telegram/access.txt` как пароли.

Перед изменениями создаётся закрытая резервная копия в `/var/backups/vless-telegram/`. При ошибке установщик восстанавливает предыдущие файлы приложения и состояние служб. Установленные пакеты ОС, кеш загрузок и добавленные разрешения 80/443 остаются. Резервные копии содержат секреты; их срок хранения контролирует администратор.

## Диагностика

```bash
sudo systemctl --no-pager status vt-vless vt-backend vt-relay vt-panel vt-caddy vt-sync.path
sudo journalctl -u vt-vless -u vt-backend -u vt-relay -u vt-caddy -n 80 --no-pager
sudo env PYTHONPATH=/opt/vless-telegram/src python3 -m vt.verify
```

Последняя команда проверяет HTTPS и ответ Telegram. Если изменения панели не применились:

```bash
sudo journalctl -u vt-sync -n 60 --no-pager
sudo systemctl start vt-sync.service
```

При ошибке сертификата проверьте A/AAAA, доступность 80/443 извне и отсутствие CDN. При ошибке VLESS проверьте ссылку, доступность удалённого сервера, SNI и ключ REALITY.

На обычной странице домена показывается стартовая страница. Замените `/opt/vless-telegram/site/index.html` своим содержимым и перезапустите `vt-relay`. Повторная установка существующую страницу сохраняет. Одинаковая стартовая страница не обеспечивает маскировку от обнаружения прокси.

## Исходники и воспроизводимость

- `src/vt/` — установщик, генератор конфигурации, панель и проверка Telegram.
- `web/` — локальные стили и JavaScript панели, без CDN.
- `dependencies.lock.json` — точные версии, адреса и контрольные суммы.
- `tools/build_installer.py` — сборка автономного `install.sh`.
- `tests/` — проверки форматов, авторизации, CSRF и конфигурации.
- `TESTING.md` — результаты интеграционной проверки и её границы.

После изменения собственных исходников:

```bash
python3 tools/build_installer.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 tools/build_installer.py --check
bash -n install.sh
```

Исходники и встроенный архив имеют один набор файлов. Архив проверяется по SHA-256 перед распаковкой. Контрольные суммы внешних компонентов проверяются отдельно; пакеты ОС устанавливаются через APT, Go-модуль — с проверкой `go.sum`.

Интернет нужен для зависимостей; «автономный» здесь означает отсутствие зависимости от других установщиков. Версии автоматически не меняются на `latest`. Обновление lock-файла требует повторной проверки и пересборки.
